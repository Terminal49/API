Use this guide to assign parties to your shipments from code instead of the dashboard bulk update.

## How parties and roles work

- A **party** is a company in your account, managed through [`/v2/parties`](/api-docs/api-reference/parties/list-parties).
- A **party role** links one party to one shipment, tracking request, or container in one role.
- Roles are a list, not a field. A shipment can carry two parties as `consignee`. To replace a party, remove its role and assign a new one.

| Role | Tracking request | Shipment | Container |
|------|------------------|----------|-----------|
| `customer` | Yes, at creation via `relationships.customer` | Yes | No |
| `shipper` | Yes | Yes | No |
| `consignee` | Yes | Yes | No |
| `notify_party` | Yes | Yes | No |
| `customs_broker` | Yes | Yes | No |
| `freight_forwarder` | Yes | Yes | No |
| `pickup_dray_carrier` | Yes | Yes | Yes |

Roles on a tracking request are copied to its shipment. This also happens when the shipment is created after the role was added, so you can set parties before the carrier responds.

You need an API key. See [Start here](/api-docs/getting-started/start-here).

## Find or create the party

Search your parties by name:

```bash
curl -s "https://api.terminal49.com/v2/parties?query=ACME" \
  -H "Authorization: Token YOUR_API_KEY"
```

If the party does not exist, [create it](/api-docs/api-reference/parties/create-a-party):

```json Request
{
  "data": {
    "type": "party",
    "attributes": {
      "company_name": "ACME LOGISTICS"
    }
  }
}
```

Keep the returned `data.id`. It is the `PARTY_ID` below.

## Create the tracking request

Create the tracking request as usual. If the shipment has a customer, pass it in `relationships.customer`. See [Add a Customer to a Tracking Request](/api-docs/in-depth-guides/adding-customer). Keep `data.id` from the response as `TRACKING_REQUEST_ID`.

## Assign roles to the tracking request

Endpoint: **POST** - [https://api.terminal49.com/v2/tracking_requests/TRACKING_REQUEST_ID/party_roles](/api-docs/api-reference/party-roles/assign-a-tracking-request-party-role)

```json Request
{
  "data": {
    "type": "party_role",
    "attributes": {
      "role": "shipper"
    },
    "relationships": {
      "party": {
        "data": {
          "id": "PARTY_ID",
          "type": "party"
        }
      }
    }
  }
}
```

```json Response
{
  "data": {
    "id": "PARTY_ROLE_ID",
    "type": "party_role",
    "attributes": {
      "role": "shipper",
      "roleable_type": "TrackingRequest",
      "roleable_id": "TRACKING_REQUEST_ID",
      "created_at": "2026-09-01T14:02:11Z",
      "updated_at": "2026-09-01T14:02:11Z"
    },
    "relationships": {
      "party": {
        "data": {
          "id": "PARTY_ID",
          "type": "party"
        }
      }
    }
  },
  "included": [
    {
      "id": "PARTY_ID",
      "type": "party",
      "attributes": {
        "company_name": "ACME LOGISTICS"
      }
    }
  ]
}
```

Send one request per role. Repeat with `"role": "consignee"` and `"role": "freight_forwarder"`.

## Read the roles on the shipment

After the shipment is created, request it with `flag[parties]=true` and include the parties:

```bash
curl -sg "https://api.terminal49.com/v2/shipments/SHIPMENT_ID?flag[parties]=true&include=party_roles.party" \
  -H "Authorization: Token YOUR_API_KEY"
```

The shipment carries a `party_roles` relationship and the `included` array holds each `party_role` and its `party`. The same flag works on `GET /v2/shipments`. `-g` stops curl from treating the brackets in `flag[parties]` as a range.

To list the roles alone, use [`GET /v2/shipments/SHIPMENT_ID/party_roles`](/api-docs/api-reference/party-roles/list-shipment-party-roles).

## Change roles on an existing shipment

Assign directly on the shipment with the same payload:

Endpoint: **POST** - [https://api.terminal49.com/v2/shipments/SHIPMENT_ID/party_roles](/api-docs/api-reference/party-roles/assign-a-shipment-party-role)

To replace the consignee:

1. List the roles and find the `party_role` with `"role": "consignee"`.
2. **DELETE** [https://api.terminal49.com/v2/shipments/SHIPMENT_ID/party_roles/PARTY_ROLE_ID](/api-docs/api-reference/party-roles/remove-a-shipment-party-role). Returns `204`.
3. **POST** the new consignee.

## Assign a dray carrier to a container

Containers accept one role, `pickup_dray_carrier`:

Endpoint: **POST** - [https://api.terminal49.com/v2/containers/CONTAINER_ID/party_roles](/api-docs/api-reference/party-roles/assign-a-container-party-role)

Read it back with [`GET /v2/containers/CONTAINER_ID/party_roles`](/api-docs/api-reference/party-roles/list-container-party-roles).

## Errors

| Status | Cause | Fix |
|--------|-------|-----|
| `401` | The party or the record belongs to another account | Use a party from `GET /v2/parties` and a shipment you created |
| `404` | Unknown shipment, tracking request, container, or party role ID | Check the ID |
| `422` `Party has already been taken` | The same party already has this role on the record | Nothing to do, the role is set |
| `422` `'x' is not a valid role` | Unknown role name | Use a role from the table above |
| `422` `Role is not allowed for Cargo` | A role other than `pickup_dray_carrier` on a container | Assign it on the shipment instead |

## Transports

| Transport | Endpoint | Best For |
|-----------|----------|----------|
| HTTP (streamable) | `POST https://mcp.terminal49.com` | Serverless, short-lived requests |

**Authentication**:
- **OAuth 2.1 (recommended)** – no API key needed. Add the connector URL, sign in with your Terminal49 credentials in the browser window your client opens, and approve access. Clients discover the authorization server (`https://auth.terminal49.com`) automatically and use authorization code with PKCE and Dynamic Client Registration.
- **API key (for clients without OAuth support)** – create a key in the [developer portal](https://app.terminal49.com/developers/api-keys) and pass `Authorization: Token YOUR_API_KEY`. Use the `Token` scheme for API keys; the `Bearer` scheme is used for OAuth access tokens, which OAuth clients obtain automatically.
- The [local stdio server](/api-docs/in-depth-guides/mcp#local-stdio-development) reads the `T49_API_TOKEN` environment variable instead.

<Tip>
Connector URL: `https://mcp.terminal49.com`. It is the canonical OAuth resource identifier, so OAuth clients (ChatGPT, Claude connectors) bind to the correct token audience.
</Tip>

## Any MCP client

Use the same hosted Streamable HTTP endpoint in any MCP-compatible client. With an OAuth-capable client, no credentials are needed — just the URL:

```json
{
  "url": "https://mcp.terminal49.com"
}
```

If your client can't run a browser OAuth flow, pass an API key instead:

```json
{
  "url": "https://mcp.terminal49.com",
  "headers": {
    "Authorization": "Token YOUR_API_KEY"
  }
}
```

See [Other MCP clients](/mcp/setup/other-clients) for details on OAuth discovery and verification.

The same [rate limits](/api-docs/in-depth-guides/rate-limiting) apply to MCP endpoints as the REST API.

### Limit the tools

Two optional request headers reduce the tools your client sees. They can only remove tools.

- `X-T49-MCP-Read-Only: true` lists only read-only tools. It removes `track_container`, `set_party_role` and `set_custom_field`.
- `X-T49-MCP-Toolsets` takes a comma-separated list of toolsets.

The toolset names are:

- `core`: every tool except the trade intelligence tools.
- `documents`: no tools yet.
- `operations`: no tools yet.
- `documents_write`: no tools yet.
- `developer`: no tools yet.
- `trade`: the [trade intelligence tools](#trade-intelligence-tools).

```json
{
  "url": "https://mcp.terminal49.com",
  "headers": {
    "Authorization": "Token YOUR_API_KEY",
    "X-T49-MCP-Read-Only": "true"
  }
}
```

The read-only header accepts `true`, `false`, `1` or `0`, in any case. Any other read-only value, an unknown toolset name, or a toolsets value made only of commas returns `400 Bad Request`.

Self-hosted deployments can enable [Sentry MCP Monitoring](https://docs.sentry.io/ai/monitoring/mcp/) by setting `SENTRY_DSN`. This captures MCP tool calls, resource reads, prompt usage, performance spans, and errors in Sentry.

Input and output recording is disabled by default. Leave `SENTRY_MCP_RECORD_INPUTS=false` and `SENTRY_MCP_RECORD_OUTPUTS=false` unless your Sentry project is approved to store shipment identifiers, references, and customer data.
</Warning>

## Tools reference

<Note>
Every tool is read-only except three. `set_party_role` and `set_custom_field` change parties and custom fields on your containers and shipments; repeating a call changes nothing more. Because they can detach a party or overwrite a field value, they are marked as destructive for MCP clients. `track_container` creates a tracking request. If your account already has an in-progress tracking request for the number, or a container with that number that is still being tracked, `track_container` returns it instead of creating a new request. A container whose shipment has stopped tracking does not count. A request is in progress while its status is `pending` or `awaiting_manifest`. When you pass `scac`, only an in-progress request under that SCAC counts. Failed or cancelled requests do not block a new one.
</Note>

### `search_container`

Find containers by container number, BL, booking, or your own reference. This is the fastest way to locate containers.

**Parameters**
- `query` *(string, required)* – container number, BL, booking, or reference

<Accordion title="Example MCP request">
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "search_container",
    "arguments": {
      "query": "MSKU4330011"
    }
  }
}
```
</Accordion>

<Accordion title="Example response">
```json
{
  "containers": [
    {
      "id": "abc-123-uuid",
      "container_number": "MSKU4330011",
      "status": "unknown",
      "shipping_line": "MAEU"
    }
  ],
  "shipments": [],
  "tracking_requests": [
    {
      "id": "def-456-uuid",
      "request_number": "MSKU4330011",
      "status": "pending",
      "scac": "MAEU"
    },
    {
      "id": "jkl-012-uuid",
      "request_number": "MSKU4330011",
      "status": "failed",
      "failed_reason": "not_found",
      "scac": "HLCU"
    }
  ],
  "total_results": 3
}
```

`total_results` counts containers, shipments, and tracking requests. The search API returns no status for a container hit, so `status` is `unknown`. Use `get_container` for the current status. `pod_terminal`, `pol_terminal`, and `destination` appear only when the search API returns them. Only a request whose tracking was stopped (status `tracking_stopped`) has `shipment_id`. A failed request has `failed_reason`. `not_found` and `invalid_number` mean the carrier rejected the number, so check the number and carrier before you track it again. `retries_exhausted` and `expired` can succeed on a later request with the same values. `duplicate` means the shipment already exists. See [failed reasons](/api-docs/in-depth-guides/tracking-request-lifecycle#permanent-reasons) for the full list. Requests that succeeded (status `created`) never appear in `tracking_requests`. Search returns the tracked container under `containers`, or the tracked shipment under `shipments` for a bill of lading or booking number. A tracking request whose number matches a returned shipment's number is left out.
</Accordion>

**Good for**
- "Find this container and tell me where it is"
- "Show all containers with reference PO-12345"

**REST equivalent**: [GET /containers](/api-docs/api-reference/containers/list-containers) with filters

### `track_container`

Start tracking a container, bill of lading, or booking number. The tool first searches your account for the number:

- If a tracking request for it is still in progress, with status `pending` or `awaiting_manifest`, the tool returns that request and its status. When you pass `scac`, only an in-progress request under the same SCAC counts.
- If a container with exactly that number is still being tracked, the tool returns that container's details in the same shape as `get_container`, plus `tracking_request_created` and `infer_result`. A container whose shipment has stopped tracking does not count, because container numbers are reused on later voyages.
- Otherwise the tool creates a tracking request. If the API reports that the number is already tracked, the tool returns `source: "duplicate"`, the existing `tracking_request.id`, and `shipment_id` when the request has a shipment. `message` holds the API's explanation, which can name a different number that the existing request is stored under.

Check `tracking_request_created` in the result. It is `false` when the tool returned an existing container, an in-progress request, or a duplicate. Container numbers are checked against the ISO 6346 check digit before the tool calls the API.

**Parameters**
- `number` *(string, required)* – container number, BL, or booking number
- `numberType` *(string, optional)* – override inference (`container`, `bill_of_lading`, `booking_number`)
- `scac` *(string, optional)* – shipping line code, e.g., `MAEU` for Maersk. Required when Terminal49 cannot infer the carrier. A container prefix such as `MSKU` names the equipment owner, not the carrier, so the tool never uses it as the SCAC.
- `refNumbers` *(string[], optional)* – your reference numbers

<Accordion title="Example MCP request">
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "track_container",
    "arguments": {
      "number": "MSKU4330011",
      "scac": "MAEU"
    }
  }
}
```
</Accordion>

**Good for**
- "Track container MSKU4330011 with Maersk"
- "Start tracking this new shipment"

**REST equivalent**: [POST /tracking_requests](/api-docs/api-reference/tracking-requests/create-a-tracking-request)

### `get_container_route`

Get a container's route: the ports in order with their arrival and departure times, and the vessel carrying the container while it is at sea.

The tool returns:
- `ports`: each port's sequence, label (`POL`, `TS1`, `POD`), name, country code, `inbound` ETA and ATA, and `outbound` ETD and ATD.
- `current_vessel`: name, IMO, voyage, position, heading, speed in knots, and the departure and arrival ports. It is `null` when the container is not at sea.
- `total_ports`: the number of ports on the route.

If Terminal49 has no route data for the container yet, the tool returns a `NoRouteData` result with a suggested alternative instead of an error.

<Warning>
This is a **paid feature**. If it is not enabled for your account, the tool returns a `FeatureNotEnabled` result. Use `get_container_transport_events` for historical movement data instead.

See [Entitlements and Paid Features](/api-docs/useful-info/entitlements) for the related Routing Data entitlement.
</Warning>

**Parameters**
- `id` *(uuid, required)* – Terminal49 container UUID

**Good for**
- "What's the routing for this container?"
- "Which transshipment ports?"
- "What vessel is it on, and where is it now?"

**REST equivalent**: [GET /containers/{id}/map_geojson](/api-docs/api-reference/containers/get-container-map-geojson)

### `list_shipments`

Return one page of shipments with verified API filters. Common inputs include exact shipment `number`, `tracking_stopped`, `actively_tracked`, `voyage_status`, `pod_code`, `pol_code`, `pod_arrival`, `created_at`, and `tags`.

Use the typed `advanced_filters` object for the full shipment filter catalog. Use `sort` for server ordering, `include_containers` for container relationships, and `page` and `page_size` for pagination. Container relationships default to excluded. Pages default to 25 rows and cannot exceed 25.

**Parameters**

- `number` *(string or string[], optional)* - exact shipment number. Arrays match any supplied number.
- `tracking_stopped` *(boolean, optional)* - shipping-line tracking stopped state.
- `actively_tracked` *(boolean, optional)* - active tracking state.
- `voyage_status` *(string, optional)* - `arrived` or `on_ship`.
- `pod_code` *(string or string[], optional)* - Port of Discharge UN/LOCODE.
- `pol_code` *(string or string[], optional)* - Port of Lading UN/LOCODE.
- `pod_arrival` *(string or string[], optional)* - arrival date expressions or bounds.
- `created_at` *(string or string[], optional)* - creation timestamps with a timezone offset.
- `tags` *(string or string[], optional)* - account shipment tags.
- `advanced_filters` *(object, optional)* - complete typed shipment filter catalog.
- `sort` *(string, optional)* - supported server sort token or tokens.
- `include_containers` *(boolean, optional)* - include related containers. Default false.
- `include_stopped_tracking` *(boolean, optional)* - include records whose tracking stopped. Default false: like the dashboard, only actively tracked records are returned unless `actively_tracked` is set. Set true for history over a past period.
- `page` *(number, optional)* - page number, starting at 1.
- `page_size` *(number, optional)* - page size. Default 25, maximum 25.

**Good for**

- "Show actively tracked shipments arriving at Los Angeles this week."
- "Find shipments by an exact Bill of Lading number."

[Filter usage, values, and pagination](/mcp/filtering-worklists) explains the inputs and result metadata.

**REST equivalent**: [GET /shipments](/api-docs/api-reference/shipments/list-shipments)

### `list_containers`

Return one page of containers with verified API filters. Common inputs include `number`, `current_status`, `pod_code`, `pol_code`, `shipping_line_scac`, `has_holds`, `has_fees`, `requires_attention`, `actively_tracked`, `arrival`, `pickup_lfd`, and `tags`.

Use the typed `advanced_filters` object for the full container filter catalog. Use `sort` for server ordering and `include` to add `shipment`, `pod_terminal`, or both. Pages default to 25 rows and cannot exceed 25.

**Parameters**

- `number` *(string or string[], optional)* - exact container number. Comma-separated numbers match any; arrays require all.
- `current_status` *(string or string[], optional)* - container status from the schema's finite vocabulary.
- `pod_code` *(string or string[], optional)* - Port of Discharge UN/LOCODE.
- `pol_code` *(string or string[], optional)* - Port of Lading UN/LOCODE.
- `shipping_line_scac` *(string or string[], optional)* - carrier Standard Carrier Alpha Code.
- `has_holds` *(boolean, optional)* - reported terminal hold state.
- `has_fees` *(boolean, optional)* - reported terminal fees.
- `requires_attention` *(boolean, optional)* - attention selection. False is not the exact complement of true.
- `actively_tracked` *(boolean, optional)* - related shipment tracking state.
- `arrival` *(string or string[], optional)* - arrival date expressions or bounds.
- `pickup_lfd` *(string or string[], optional)* - pickup Last Free Day date expressions or bounds.
- `tags` *(string or string[], optional)* - related shipment tags.
- `advanced_filters` *(object, optional)* - complete typed container filter catalog.
- `sort` *(string, optional)* - supported server sort token or tokens.
- `include` *(string[], optional)* - `shipment`, `pod_terminal`, or both.
- `include_stopped_tracking` *(boolean, optional)* - include records whose tracking stopped. Default false: like the dashboard, only actively tracked records are returned unless `actively_tracked` is set. Set true for history over a past period.
- `view` *(string, optional)* - `compact` (default) returns number, status, availability, POD terminal, key dates, LFD, holds, fees and the shipment's BL, carrier and POD ETA; `full` returns every attribute.
- `page` *(number, optional)* - page number, starting at 1.
- `page_size` *(number, optional)* - page size. Default 25, maximum 25.

**Good for**

- "Show available containers at Los Angeles with reported terminal holds."
- "List actively tracked containers approaching their pickup Last Free Day."

[Filter usage, values, and pagination](/mcp/filtering-worklists) explains the inputs and result metadata.

**REST equivalent**: [GET /containers](/api-docs/api-reference/containers/list-containers)

### `summarize_containers`

Count containers grouped by one dimension, using the same filters as `list_containers`. Use it for "how many" and "break down by" questions; use `list_containers` for "which ones". Like the dashboard, only actively tracked containers are counted unless `include_stopped_tracking` is true.

**Parameters**

- The filters accepted by `list_containers` (including `advanced_filters` and `include_stopped_tracking`).
- `group_by` *(string, required)* - `pod_terminal`, `current_status`, `shipping_line`, `port_of_discharge`, `hold_type`, `pickup_lfd_date` or `pod_arrival_date`.

Counts come from `GET /v2/containers/summary` in one request. `hold_type` counts each distinct current POD hold name, including pending holds, so a container with two holds counts twice; dates follow dashboard display timezones, falling back to UTC when missing or invalid. Groups are ordered by count and capped at 200; `truncated` is true when there are more.

**Good for**

- "How many containers are at risk at each terminal?"
- "Break down containers on hold by hold type."

### `list_parties`

Find the companies on the account's shipments (customers, shippers, consignees, customs brokers, freight forwarders, dray carriers) by name and return their IDs. Pass an ID to `list_containers` or `summarize_containers` through `advanced_filters.parties`, keyed by role, such as `{ "customer": "<id>" }`.

**Parameters**

- `search` *(string, optional)* - company name or part of one; case and punctuation are ignored.
- `limit` *(number, optional)* - most parties to return. Default 25, maximum 50.

**Good for**

- "How many containers does Acme have at the terminal?" (find Acme, then filter by `customer`)
- "Which containers is Ray Drayage picking up?" (find the carrier, then filter by `pickup_dray_carrier`)

### `set_party_role`

Attach a party to containers or shipments in a role, replace the party in that role, or detach it. Find the party ID with `list_parties` first.

**Parameters**

- `container_ids` or `shipment_ids` *(array of IDs)* - 1 to 50 records; pass one, not both.
- `role` *(string)* - containers support `pickup_dray_carrier`; shipments also support `shipper`, `consignee`, `notify_party`, `customs_broker`, `customer`, and `freight_forwarder`.
- `party_id` *(string)* - the party's ID.
- `action` *(string)* - `add`, `replace`, or `remove`. `add` attaches the party beside any others in the role. A record holds one `pickup_dray_carrier` and one `customer`, so `add` fails on a record where a different party already holds one of those; use `replace` to swap it. `replace` makes the party the only one in the role and detaches the rest. It does not replace a shipment's `customer`: remove the current customer, then add the new one. `remove` detaches the party.

Returns the records that changed, those that already matched, and any that failed. A call stops after about 20 seconds; on the hosted server that time starts when the request arrives, so checking your credentials counts toward it. Records it had not started saving by then are listed in `not_attempted`, unchanged, so you can call again with them. A record that was still being saved when time ran out is listed in `failed`; check it before you call again.

**Good for**

- "Set the drayage carrier to Manzo Transport on these containers." (`replace`)

- `value` *(string, number, boolean, array of strings, or null)* - the new value; pass an array of option values for a multi-select field, and `null` to clear the field.

Returns the records that changed, those that already matched, and any that failed. A call stops after about 20 seconds; on the hosted server that time starts when the request arrives, so checking your credentials counts toward it. Records it had not started saving by then are listed in `not_attempted`, unchanged, so you can call again with them. ## Trade intelligence tools

Trade intelligence answers market questions about US ocean imports: who imports a product, what a named company imports and how that is changing, where goods come from, and port, carrier, and lane volumes. It is built from US Customs bill-of-lading records from January 2022 to today, refreshed daily. These tools read market data, not your account's shipments, and all of them are read-only.

<Note>
Trade intelligence is enabled per account. Without it, each tool replies that trade intelligence isn't enabled for the account. To turn it on, contact support@terminal49.com.
</Note>

Keep these in mind when you read the answers:

- Volume is physical containers, each counted once. Values are estimates, not declared customs values.
- `get_trade_trends` and `get_trade_breakdown` include the current month, which is still incomplete, unless you set `until`. Compare full months against the same months a year earlier.
- A company can appear under several names and once per US state. Some importers keep their names off the records or ship under a forwarder, so low volume for a well-known company is a floor, not its size.
- Forwarders and customs brokers appear among importers. A high `share_as_notify_party` suggests a logistics provider, but large cargo owners can also be listed mostly as notify party, so weigh the company name and product mix too.
- Don't add volumes across products or companies. Carriers appear under spelling variants, so merge them before computing shares.
- Lane fields (`pol`, `pol_country`, `container_type`) can't be combined with importer or product fields (`company`, `company_state`, `hs4`, `hs2`) in one request, and they don't support `estimated_value`. Use containers or TEUs for lane questions.

---

### `search_importers`

Find US importers by company name (typos and partial names are fine), by what they import, or both. Each result covers a 12-month search window, which can end a month or two before the last full month: containers, the consignee and notify-party split, twenty-foot equivalent units (TEUs), estimated value, and top ports, origin countries, carriers, and products. Results are ordered by match quality, not size.

**Parameters**

- `name` *(string, optional)* - company name.
- `imports` *(string, optional)* - what the company imports, in plain words.
- `state`, `port_of_discharge`, `origin_country` *(string, optional)* - narrow the search.
- `min_containers` *(number, optional)* - minimum containers in the search window.
- `limit` *(number, optional)* - default 10, maximum 25.

**Good for**

- "Who are the importers of frozen shrimp in Florida?"
- "Find Example Outdoor Supply's importer records."

---

### `get_importer_profile`

One importer's imports over full calendar months ending last month: totals, a monthly series, US ports, origin countries, carriers, destination states, and products with estimated value. Use `months: 24` to compare the latest months with the same months a year earlier.

**Parameters**

- `company_name` *(string, required)* - the exact name from `search_importers`.
- `company_state` *(string, optional)* - one state; omit to combine all of the company's locations.
- `months` *(number, optional)* - default 12, maximum 60.

**Good for**

- "What does this competitor import, and is it growing?"

---

### `search_commodities`

Turn a product description or Harmonized System (HS) code prefix into four-digit HS codes, with the goods commonly declared under each code, the number of importers, and 12-month estimated value. Check the common goods before relying on a code.

**Parameters**

- `query` *(string, required)* - such as `office chairs` or `94`.
- `limit` *(number, optional)* - default 8, maximum 20.

Each code lists up to 15 common goods; `common_goods_not_shown` counts any left out.

---

### `rank_importers`

Rank US importers by containers over full calendar months for a product, a US port, an origin country, or any combination. The ranking includes forwarders and customs brokers.

**Parameters**

- `hs4`, `port_of_discharge`, `origin_country` *(string, optional)* - filters.
- `months` *(number, optional)* - default 12, maximum 60.
- `limit` *(number, optional)* - default 20, maximum 50.

**Good for**

- "Who are the top importers of office chairs through Savannah?"

---

### `get_trade_trends`

A time series of containers, TEUs, or estimated value by month, quarter, or year, split by up to two dimensions and filtered by any of them. By default it covers the 24 months ending with the current, incomplete month. History goes back to January 2022.

**Parameters**

- `measure` *(string, optional)* - `containers` (default), `teus`, or `estimated_value`. `estimated_value` is not available by lane: a request that also groups or filters by `pol`, `pol_country`, or `container_type` is rejected.
- `group_by` *(array, optional)* - up to two dimensions, such as `origin_country` or `pod`.
- `filters` *(object, optional)* - product, importer, origin, port, coast, carrier, state, and equipment filters. The `company` filter matches every name containing the text.
- `interval` *(string, optional)* - `month` (default), `quarter`, or `year`.
- `since`, `until` *(string, optional)* - `YYYY-MM`, inclusive.
- `top` *(number, optional)* - largest groups to keep, default 10, maximum 25.

**Good for**

- "Has Vietnam overtaken China for furniture imports?"

---

### `get_trade_breakdown`

Nested totals over one to three dimensions, such as region, country, and US port, with a grand total and subtotals at every level. By default it covers the 12 months ending with the current, incomplete month, so it is not 12 full months. For an annual total, set `since` and `until` to 12 full months.

**Parameters**

- `dims` *(array, required)* - one to three dimensions, outermost first.
- `measure`, `filters`, `since`, `until` - as for `get_trade_trends`. `estimated_value` is not available by lane: a request that also breaks down or filters by `pol`, `pol_country`, or `container_type` is rejected.
- `top` *(number, optional)* - largest children under each parent, default 10, maximum 20.

**Good for**

- "What share of seafood imports lands on each coast?"

---

### `get_trade_data_coverage`

What the data covers right now: where history starts, the latest month and whether it is incomplete, the last full month, and when the data was last built. No parameters.

## Resources reference
